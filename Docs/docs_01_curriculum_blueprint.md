# Curriculum Blueprint

## Desarrollo de Software con IA y Agentes Autónomos bajo Scrum

**(Antigravity + AI-Augmented Engineering)**

---

# 1. Resumen Ejecutivo

Este programa profesional avanzado está diseñado para transformar desarrolladores senior, arquitectos y líderes técnicos en **AI-Augmented Engineers capaces de supervisar agentes autónomos bajo marcos ágiles (Scrum)**.

El curso responde a la evolución del desarrollo 2025–2026:

- Desarrollo multi-archivo asistido por agentes
- Arquitectura generada y validada por IA
- CI/CD automatizado con supervisión humana
- Testing impulsado por modelos
- Gobernanza técnica y ética en entornos AI-driven

El enfoque no es enseñar herramientas aisladas, sino **enseñar a dirigir y supervisar sistemas de desarrollo aumentados por IA**.

Se estructura bajo:

- Scrum como marco operativo
- Antigravity como entorno de agentes
- Integración de prácticas industriales: CI/CD, testing, seguridad y arquitectura limpia

El programa está diseñado para:

- Marketplace (versión modular optimizada)
- Plataforma propia (cohorte premium + B2B)

# 8. Checklist de Calidad del Blueprint

Este checklist se usa como **Definition of Done** del diseño curricular. Si falta un ítem crítico, el blueprint **no está listo** para producción.

## 8.1 Checklist Académico
- [ ] Cada unidad tiene **objetivo específico** y **resultados de aprendizaje medibles** (verbos observables).
- [ ] Los resultados están alineados a **Bloom** (Aplicar/Analizar/Evaluar/Crear predominan).
- [ ] Existe coherencia: **unidad → práctica → evidencia → evaluación**.
- [ ] Hay **progresión** (de fundamentos → ejecución supervisada → gobernanza → liderazgo → capstone).

## 8.2 Checklist Técnico-Industrial
- [ ] Cada unidad incluye al menos **1 práctica** con artefacto verificable (repo / pipeline / tests / docs).
- [ ] Se define **Definition of Done** técnico mínimo para entregables.
- [ ] Se incorporan gates de calidad: lint, tests, coverage, seguridad básica.
- [ ] Las herramientas y versiones están especificadas y son reproducibles (Docker/Dev Containers recomendado).

## 8.3 Checklist de Integración con Agentes (Antigravity)
- [ ] Se explicita **qué delega el alumno** al agente y **cómo lo supervisa**.
- [ ] Se exige **trazabilidad**: prompts, decisiones, cambios y revisión humana.
- [ ] Existe una guía de “fallos esperables” (alucinación, overreach, cambios no solicitados) y mitigación.

## 8.4 Checklist de Evaluación
- [ ] Rúbricas con criterios técnicos, de arquitectura y de supervisión IA.
- [ ] Ponderaciones por modalidad (intensiva, semestral, ejecutiva).
- [ ] Evidencias auditables (commit history, PRs, reportes CI, ADRs, demo).

## 8.5 Checklist de Producto (Monetización)
- [ ] Existe separación clara de oferta:
  - Marketplace: contenido modular + labs básicos + CTA a upgrade.
  - Plataforma propia: cohorte premium, feedback, defensa técnica, B2B.
- [ ] Se define qué se entrega como **plantillas descargables** y qué se mantiene premium.

# 9. Detalle por Unidad (Objetivo, Contenidos, Labs, Entregables y DoD)

> Nota: este apartado es el “contrato” operativo del curso. Si una unidad no produce un entregable usable, se rediseña.

## U1. Fundamentos de AI-Augmented Engineering
**Objetivo:** Explicar y aplicar el paradigma de desarrollo con IA/Agentes, identificando límites, riesgos y oportunidades en ingeniería de software.

**Temas clave:**
- De autocompletado a agentes autónomos
- Tipos de IA aplicados al SDLC (generativa/predictiva/validación)
- Riesgos: sesgos, alucinaciones, fuga de datos, supply chain

**Laboratorio:** “Primer flujo supervisado”
- El alumno pide a un agente generar una función + tests + README (mini-scope).
- Luego valida y corrige.

**Entregables:**
- Mini reporte técnico (1–2 páginas) + repo mínimo con tests.

**Definition of Done (DoD) mínimo:**
- Repo compila/ejecuta, tests pasan, README explica uso, commit history.

---

## U2. Scrum para Entornos con Agentes
**Objetivo:** Operar Scrum adaptado a equipos con agentes (AI-Augmented Scrum), definiendo DoR/DoD, backlog y eventos.

**Temas clave:**
- Scrum roles/eventos/artefactos
- Backlog delegable a agentes (tareas “agent-ready”)
- DoR/DoD con gates de calidad

**Laboratorio:**
- Crear Product Backlog de un sistema pequeño + Sprint Goal + Sprint Backlog.

**Entregables:**
- Backlog (historias + criterios de aceptación) + tablero (Trello/Jira).

**DoD mínimo:**
- Historias con criterios claros, tareas delegables, riesgos identificados.

---

## U3. Arquitectura Supervisada por IA
**Objetivo:** Diseñar arquitectura con ayuda de agentes, documentando decisiones (ADRs) y validando calidad (seguridad/mantenibilidad).

**Temas clave:**
- Arquitectura limpia / hexagonal (según caso)
- ADRs y diagramas (C4 recomendado)
- Modelado de componentes, interfaces, datos

**Laboratorio:**
- Agente propone arquitectura + el alumno valida y ajusta.

**Entregables:**
- 3 ADRs + diagramas (C4 L1/L2) + threat checklist básico.

**DoD mínimo:**
- ADRs con trade-offs, diagramas consistentes, decisiones justificadas.

---

## U4. Prompt Engineering Profesional (Delegación a Agentes)
**Objetivo:** Diseñar instrucciones precisas para agentes: alcance, restricciones, criterios de aceptación, pruebas y límites.

**Temas clave:**
- Prompt como especificación técnica
- Control de alcance (guardrails)
- Estrategias: plan-first, test-first, diff-only, incremental

**Laboratorio:**
- Construir librería de prompts: feature, refactor, tests, docs, pipeline.

**Entregables:**
- Catálogo de prompts reutilizables + plantilla “Agent Task Spec”.

**DoD mínimo:**
- Prompts reproducibles, con criterios verificables y anti-overreach.

---

## U5. Implementación con Agentes (Antigravity)
**Objetivo:** Implementar una feature real multi-archivo, supervisando el agente y aplicando calidad industrial.

**Temas clave:**
- Implementación incremental (PRs)
- Code review asistido
- Refactor seguro

**Laboratorio:**
- Feature end-to-end: API + UI mínima + persistencia simple.

**Entregables:**
- PRs con commits, feature funcionando, changelog.

**DoD mínimo:**
- Tests unitarios, lint OK, PR descrito, no secretos en repo.

---

## U6. Testing Automatizado y Validación
**Objetivo:** Generar y mantener suites de tests con apoyo de IA, midiendo cobertura y confiabilidad.

**Temas clave:**
- Unit/integration tests
- Coverage & mutation mindset
- Flaky tests y estabilización

**Laboratorio:**
- Generar tests + elevar cobertura a umbral objetivo.

**Entregables:**
- Reporte de cobertura + suite tests + guía de ejecución.

**DoD mínimo:**
- Coverage >= umbral acordado (p.ej. 70%), tests reproducibles.

---

## U7. CI/CD y DevOps Aumentado por IA
**Objetivo:** Construir pipeline CI/CD que ejecute build/test/quality gates y prepare despliegue.

**Temas clave:**
- GitHub Actions/Jenkins (según track)
- Gates: lint, tests, SAST básico
- Versionado y releases

**Laboratorio:**
- Pipeline CI con gates + artefactos.

**Entregables:**
- Workflow YAML + evidencia ejecución + badges.

**DoD mínimo:**
- Pipeline corre en PR, bloquea si falla calidad.

---

## U8. Gobernanza, Seguridad y Ética
**Objetivo:** Definir políticas y controles para uso responsable de IA en desarrollo: privacidad, licencias, seguridad y accountability.

**Temas clave:**
- Riesgos de prompts con datos sensibles
- Licenciamiento OSS y compliance
- Políticas de uso de agentes

**Laboratorio:**
- Crear política “AI Usage Policy” + checklist de revisión.

**Entregables:**
- Política + checklist + matriz de riesgos.

**DoD mínimo:**
- Riesgos identificados, mitigaciones accionables.

---

## U9. Gestión Técnica y Liderazgo AI
**Objetivo:** Operar sprints con equipos (humanos + agentes), midiendo productividad, calidad y riesgos.

**Temas clave:**
- Métricas útiles (no vanity): lead time, defect escape rate, coverage trend
- Gestión de deuda técnica
- Revisión de desempeño del agente

**Laboratorio:**
- Simulación Sprint: planning → daily → review → retro.

**Entregables:**
- Sprint report + métricas + retro actions.

**DoD mínimo:**
- Evidencia de decisiones, acciones de mejora.

---

## U10. Proyecto Final Integrador
**Objetivo:** Entregar un producto completo con ingeniería profesional, usando agentes de manera controlada y demostrando dominio.

**Entregables mínimos:**
- Backlog + sprints + repo
- Arquitectura (ADRs + diagramas)
- Implementación multi-archivo
- Tests + coverage report
- CI pipeline
- Documentación técnica + demo

**DoD mínimo:**
- Demo funcional, repo limpio, pipeline verde, documentación lista.

# 11. Reglas Operativas (Versiones Mínimas y Reproducibilidad)

## 11.1 Requisitos mínimos de software
- **Node.js:** 18 LTS o superior
- **Python:** 3.10 o superior
- **Git:** 2.40+
- **Docker Desktop / Engine:** 24+
- **Editor:** VS Code recomendado

## 11.2 Reproducibilidad
- Se recomienda **Dev Containers** o Docker Compose para labs.
- Todo entregable debe incluir: `README`, instrucciones de ejecución y variables de entorno documentadas.

## 11.3 Buenas prácticas de seguridad
- No subir API keys.
- Usar `.env.example`.
- Revisar dependencias (dependabot u otra política).
