# Guía del Estudiante – Unidad 1  
## AI-Augmented Engineering: Supervisión Estratégica de Agentes

---

# 1. Propósito de la Unidad

Esta unidad introduce el paradigma de **AI-Augmented Engineering**, donde el desarrollador evoluciona hacia un rol de **Supervisor Estratégico de Agentes**.

El objetivo no es aprender a “usar IA”, sino aprender a **gobernarla con criterio técnico, métricas y disciplina profesional**.

---

# 2. Objetivos de Aprendizaje (Medibles)

Al finalizar la unidad, el estudiante será capaz de:

1. Explicar el cambio de paradigma entre desarrollo tradicional y desarrollo supervisado por IA.
2. Diseñar un prompt técnico estructurado con restricciones claras.
3. Delegar una tarea de implementación a un agente IA de forma controlada.
4. Validar el resultado mediante métricas objetivas (coverage, CI, lint).
5. Identificar riesgos de deuda técnica acelerada por uso irresponsable de IA.

---

# 3. Competencias Desarrolladas

| Competencia | Nivel Bloom | Evidencia |
|-------------|------------|-----------|
| Supervisión técnica de IA | Analizar | Repo funcional + revisión crítica |
| Redacción de prompts profesionales | Aplicar | Prompt documentado con restricciones |
| Validación con métricas | Evaluar | CI verde + coverage ≥ 70% |
| Pensamiento arquitectónico inicial | Analizar | Documento de diseño breve |

---

# 4. Prerrequisitos Técnicos

Antes de comenzar esta unidad debes:

- Conocer fundamentos básicos de programación (JS o Python).
- Comprender qué es Git.
- Saber ejecutar comandos básicos en terminal.
- Tener Node.js instalado (v18+ recomendado).
- Tener cuenta GitHub activa.

---

# 5. Tiempo Estimado de Dedicación

- Video clase: 25 minutos
- Demo práctica: 30 minutos
- Laboratorio: 60–90 minutos
- Reflexión y documentación: 20 minutos

**Tiempo total estimado:** 2.5 – 3 horas

---

# 6. Actividad Principal – Laboratorio

## Contexto

Desarrollar una función de validación de usuario delegando la implementación a un agente IA bajo supervisión técnica.

## Entregables

- Repositorio funcional.
- Prompt utilizado documentado.
- Evidencia de tests automatizados.
- Coverage mínimo 70%.
- CI verde.
- README actualizado.

---

# 7. Definition of Ready (Para la Historia de la Unidad)

- Historia claramente definida.
- Criterios de aceptación escritos.
- Edge cases identificados.
- Restricciones técnicas establecidas.

---

# 8. Definition of Done

La tarea está completa cuando:

- El código cumple criterios definidos.
- Tests automatizados pasan.
- Coverage ≥ 70%.
- CI ejecuta sin fallos.
- Prompt y decisiones documentadas.

---

# 9. Checklist de Aprendizaje

Marca cuando puedas responder afirmativamente:

- [ ] Puedo explicar el flujo Antigravity.
- [ ] Sé redactar un prompt con restricciones.
- [ ] No acepto código generado sin validarlo.
- [ ] Sé medir coverage.
- [ ] Comprendo el riesgo de deuda técnica acelerada.

---

# 10. Evaluación

La unidad se evalúa mediante:

- Laboratorio práctico (rúbrica técnica).
- Revisión del prompt.
- Validación de métricas.
- Reflexión crítica (breve reporte).

---

# 11. Recursos Complementarios

---

# 12. Reflexión Final

Responder en máximo 300 palabras:

> ¿Cómo cambia tu rol profesional cuando la generación de código deja de ser el cuello de botella?
